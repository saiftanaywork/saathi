# Saathi — Design System

Source of truth is `css/styles.css`. This doc is a map of it, not a
duplicate — when they disagree, the CSS wins and this file should be
updated to match.

## Tokens (CSS custom properties, `:root`)

**Color** — `--paper`, `--paper-alt`, `--card`, `--ink`, `--ink-soft`,
`--ink-faint`, `--line`, `--line-soft`, plus five accent pairs
(`--terracotta`/`-deep`/`-tint`, `--teal`, `--ochre`, `--rose`, `--moss`,
each with a `-tint` variant for backgrounds). All redefined under
`@media (prefers-color-scheme: dark)` and again under
`:root[data-theme="dark"]` — see [`docs/BRAND.md`](./BRAND.md) for the
palette's design intent.

**Elevation** — `--shadow-soft` (cards at rest), `--shadow-lift` (hover/
active state).

**Radius** — `--radius-sm` (9px), `--radius-md` (14px), `--radius-lg`
(22px). Cards and panels use `-lg`; smaller controls use `-sm`/`-md`.

**Type** — Fraunces (display/headings) and Work Sans (body/UI), see
BRAND.md. No spacing scale is tokenized as CSS variables; spacing is
hand-tuned per component (this is a small enough site that a formal spacing
scale hasn't been worth the abstraction yet — revisit if the component
count grows significantly).

## Layout primitives

- `.container` — max-width content wrapper used on every page.
- `.section` / `.section-alt` — vertical page rhythm, alternating
  background tint.
- `.browse-layout` — sidebar-filters + main-content grid (collapses to
  stacked on mobile).

## Icons

All icons are inline SVG generated by the `icon()` helper in
`js/constants.js` — no icon font, no external icon library. Add a new icon
by adding a new `pathData => icon(pathData)` export there, not by pulling
in a dependency.

## Conventions for adding UI

- Reuse an existing class before inventing a new one — check this table
  first.
- New accent colors are not expected; the five-color accent system is
  meant to stay closed (it's tied to `AVATAR_ACCENTS` in
  `js/constants.js` and the hash-based assignment in `accentFor()`).
- Dark mode is not optional to support — every new color must be defined in
  both the light `:root` block and the two dark blocks (media query +
  `[data-theme="dark"]`), matching the existing token pattern.
